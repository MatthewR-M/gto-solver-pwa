# GTO Solver PWA

An offline-first poker solver for **personal study**, installable on iPhone
as a home-screen web app. It runs a real CFR+ solver (over an abstracted
heads-up postflop game) entirely on the device — no backend, no accounts,
no network calls, no analytics.

> **Study use only.** Using real-time assistance while playing online poker
> violates most poker sites' rules and can get accounts banned and funds
> seized. Use this tool for study and hand review away from the tables.

## What it does

- **Spot Solver** — set a board, both players' ranges (editable 13×13
  grids), pot, stacks, and a bet-size abstraction; run CFR+ in a Web Worker
  with stop/resume and iteration/time budgets. Output: per-bucket (per-hand)
  action frequencies, range aggregates, EV, equity, and a convergence
  readout (exploitability as % of pot).
- **Quick Advisor** — preflop questions are answered instantly from
  precomputed charts; postflop questions run a small fast solve.
- **Preflop Charts** — open / vs-open / 3-bet / 4-bet charts by position and
  stack depth (50/100/200bb), generated by this project's own script (see
  "Preflop chart method" below — they are a heuristic equity model, **not**
  solver output).

Game scope: No-Limit Hold'em, 6-max cash, heads-up postflop (single-raised
and 3-bet pots). Multiway pots, tournaments/ICM, and other variants are out
of scope.

## Setup (Windows, PowerShell)

Prerequisite: Node.js 20+ from <https://nodejs.org> (LTS installer). After
installing, **close and reopen PowerShell** so `node` and `npm` are on your
PATH.

Get the code (pick one):

```powershell
# Option A: clone (after creating the empty repo on github.com)
git clone https://github.com/<your-username>/gto-solver-pwa.git
cd gto-solver-pwa

# Option B: extract a release zip
Expand-Archive .\gto-solver-pwa.zip -DestinationPath . 
cd gto-solver-pwa
```

Install and run:

```powershell
npm install
npm run dev        # local dev server
npm test           # engine + validation test suite (Node)
npm run build      # production build into dist\
npm run preview    # serve the production build locally
```

Optional data regeneration (not needed for normal use; the generated files
are committed):

```powershell
npm run gen:preflop   # regenerate src\data\preflop.json  (~1 minute)
npm run gen:icons     # regenerate public\icons\*.png
npm run bench         # rewrite BENCHMARKS.md with local measurements
```

## Updating and redeploying

1. Change code, commit, and push to `main`:

   ```powershell
   git add -A
   git commit -m "Describe the change"
   git push
   ```

2. GitHub Actions runs lint → tests → build, then deploys to GitHub Pages
   automatically (see `.github/workflows/ci.yml`). Watch progress under the
   repo's **Actions** tab.
3. On the iPhone, open the installed app while online. When the new version
   is ready, an **"update available" banner** appears — tap *Update now*.

One-time repository setup for Pages: in the GitHub repo, go to
**Settings → Pages → Build and deployment → Source: GitHub Actions**.

## Installing on iPhone

1. Open the deployed URL in **Safari** (must be Safari, not Chrome).
2. Tap **Share** → **Add to Home Screen** → **Add**.
3. Launch it from the home screen once while online so the service worker
   can precache the app. After that it works fully in airplane mode.
4. The app requests persistent storage, but iOS may still evict site data
   for apps unused over long periods; if the app ever loads blank offline,
   open it once online to re-cache.

## Architecture

```
engine/            Pure TypeScript, no DOM. Runs in Node (tests) and in a
                   Web Worker (app).
  cards.ts         Card encoding + fast packed-integer 7-card evaluator.
  equity.ts        Exact river/turn equity; seeded Monte Carlo equity.
  cfr.ts           Explicit game tree in typed arrays + CFR+ (alternating
                   updates, linear averaging) + exact best-response
                   exploitability.
  games.ts         Kuhn / Leduc / analytic river toy (validation targets).
  postflop.ts      The abstracted postflop game: equity-percentile card
                   buckets, single-street betting tree, bucket-vs-bucket
                   showdown equity matrix, pre-flight memory estimate.
src/
  screens/         Spot Solver, Quick Advisor, Preflop Charts.
  worker/          Web Worker hosting the solver session.
  lib/ranges.ts    Range presets and chart lookups.
  data/preflop.json  Generated charts (committed).
scripts/
  generate-preflop.ts  Chart generation (method below).
  benchmarks.ts        Local benchmark harness -> BENCHMARKS.md.
  generate-icons.mjs   Programmatic PNG icons.
tests/             Vitest suite (evaluator enumeration, CFR validation,
                   postflop behavior).
```

The engine is single-threaded by design: GitHub Pages cannot send
COOP/COEP headers, so `SharedArrayBuffer` multithreading is unavailable;
a Web Worker keeps solving off the UI thread instead.

## How the solver works — and its approximations

Every number the app shows should be read with these in mind. The app
labels them in the UI as well.

1. **Card abstraction.** Each player's combos are grouped into N buckets
   (default 10) by equity percentile against the opposing range, with equal
   range weight per bucket. A hand's strategy is its bucket's strategy.
2. **One street of betting.** Only the current street is solved as a
   betting round (configurable sizes: by default 33%/75% of pot plus
   all-in, at most 2 raises). When betting closes, the hand goes to
   showdown.
3. **Future streets = equity.** Instead of modelling turn/river betting,
   showdown payoffs use a bucket-vs-bucket equity matrix computed by Monte
   Carlo over the remaining runout. This assumes *perfect equity
   realization* — real hands realize more or less than their raw equity
   depending on position and playability, so strategies will differ from a
   full solver's, typically betting less than a full solution would.
4. **Card removal between players is approximated.** The root deals the
   two buckets independently (weights proportional to bucket range
   weights), so the fact that two specific combos can't share a card is
   ignored at the bucket level. Removal against the board is exact.
5. **Exploitability is for the abstract game.** It is computed exactly
   (best-response), but for the abstracted game above; it is a *lower
   bound* on the exploitability of the induced strategy in the real game,
   not a measurement of it. Nothing in this app is a full-game GTO
   solution, and outputs are labeled accordingly.

Additional limits:

- Ranges are the two players' ranges on one street; preflop action is
  represented only through the ranges you enter (presets come from the
  charts below).
- Stacks are a single effective stack shared by both players; the
  starting pot is treated as contributed equally by both (utilities are
  relative to owning half the pot).
- Bet amounts are rounded to whole chips.
- Peak memory is estimated before solving; spots estimated above ~250 MB
  are refused with an explanation (reduce sizes/buckets/raises). The
  abstraction sizes that fit comfortably are far below this in practice
  (a default flop spot estimates ~0.3 MB).
- Performance on a real iPhone has **not** been measured (no device was
  available during development). `BENCHMARKS.md` contains desktop Node
  numbers only, labeled as such. On this sandbox CPU a reduced flop spot
  reaches 0.38% of pot in 10 s; expect a phone to be several times slower.

## Preflop chart method

`scripts/generate-preflop.ts` builds the charts from first principles —
no published or proprietary ranges are used as input:

1. Monte Carlo all-in equity for all 169 hand classes (own evaluator,
   seeded), vs a random hand and vs specific ranges.
2. RFI: positions open the equity-ranked top classes up to a target share
   of combos (UTG 13%, MP 16%, CO 22%, BTN 40%, SB 35%).
3. Vs-open: 3-bet at equity ≥ 0.56 vs the opener's range; call above a
   position/price threshold (BB 0.435, SB 0.455, IP 0.45); selected suited
   classes below calling strength 3-bet at 50% as bluffs (a modelling
   choice so the 3-bet range isn't pure value).
4. Vs-3-bet: 4-bet at equity ≥ 0.55 vs the 3-bet range; call in
   [0.47, 0.55).
5. Depths: 50bb shifts call/4-bet thresholds +0.01 and drops bluff
   3-bets; 200bb shifts −0.01. RFI targets don't vary with depth.

These are heuristic thresholds on top of real equities — a reasonable
reference baseline, not equilibrium output. The app labels them as such.

## Validation

The test suite (`npm test`) checks:

- **Evaluator** against brute-force enumeration of all 133,784,560
  seven-card hands (category counts match the known combinatorial values
  exactly). Note: this one test takes ~75 s.
- **Monte Carlo equity** against exact enumeration on a turn board
  (agreement within 0.01).
- **Kuhn poker**: CFR reproduces the known game value −1/18 for player 1
  (within 0.002) with exploitability < 0.002.
- **Leduc Hold'em**: exploitability decreases toward 0 (< 0.05 after
  5,000 iterations in the test configuration).
- **Analytic river toy game** (nuts-or-air vs bluff-catcher): CFR matches
  the closed-form solution derived in `engine/games.ts` — bluff 1/3,
  call 2/3, value 50/3 — within tolerance.
- **Postflop behavior**: a dominating-hand spot (AA vs a mixed flop
  range) bets as it must; oversized trees are refused; results are
  deterministic for a fixed seed; stop/resume equals continuous solving.

## Offline behavior & manual iPhone checklist

Automated offline testing with Playwright passes against the production
build (`node scripts/offline-test.mjs` after `npm run build`): the app
loads, the service worker takes control, and after switching the browser
context offline the app reloads from cache with charts and advisor fully
functional. (In sandboxed environments without a Playwright-managed
browser, the script accepts a `PW_EXECUTABLE_PATH` override.) Still
verify the real device flow yourself:

1. Install the app (steps above) and open it once online; wait a few
   seconds (first load precaches the app shell).
2. Run a small solve and open all three tabs (this forces every asset to
   load).
3. Enable **airplane mode**.
4. Kill the app (swipe it away) and relaunch from the home screen.
   Expected: the app loads fully.
5. Run a solve offline and look up a preflop chart. Expected: both work.
6. Turn airplane mode off. After a new deploy, reopening the app should
   show the "update available" banner within a minute or two.
